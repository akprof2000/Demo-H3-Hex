# `H3Grid` — сетка гексагонов на весь экран 🕸️

**▶️ [Живое демо](https://akprof2000.github.io/Demo-H3-Hex/)** — вкладка «Сетка гексагонов»
открывается по умолчанию. Там же переключатель на демо `H3Map` с данными.
Исходники демо: [`example/GridDemo.tsx`](../example/GridDemo.tsx).

Руководство для того, кто открыл этот файл первым. Здесь разобрано, что делает
компонент, из чего он собран, почему сделан именно так и что крутить под себя.

Весь код в `src/gridGeometry.ts`, `src/H3GridLayer.ts`, `src/H3Grid.tsx`
прокомментирован построчно — этот документ объясняет «зачем», код объясняет «как».

---

## 1. Что это такое

`H3Grid` берёт видимую область карты и закрашивает её **границами гексагонов H3**
заданного разрешения. Заливки нет — только линии. Получается сетка «миллиметровки»,
разложенная по поверхности Земли.

Зачем это нужно на практике:

- показать пользователю, **какого размера ячейка** на текущем масштабе — до того,
  как он загрузит данные;
- дать выбрать ячейку мышью и отправить её индекс на бэкенд;
- отладка: сразу видно, совпадает ли ваша агрегация с сеткой H3;
- подложка под собственные слои — например, разметка зон покрытия.

### Чем отличается от `H3Map`

| | `H3Map` | `H3Grid` |
| --- | --- | --- |
| Откуда берутся ячейки | приходят с бэкенда | **придумываются на лету** по экрану |
| Что рисуется | заливка + обводка | только линии |
| Есть значения | да, число на ячейку | нет, только индексы |
| Что грузится по сети | данные | ничего |

Ключевая мысль: у `H3Grid` **нет входных данных вообще**. Список ячеек
вычисляется из прямоугольника экрана функцией `polygonToCells`.

## 2. Самый быстрый старт

```tsx
import { H3Grid } from 'react-h3-map';
import 'maplibre-gl/dist/maplibre-gl.css';

export default function App() {
  return <H3Grid />; // 🗺️ OSM + сетка, разрешение подбирается по зуму
}
```

Родитель должен иметь ненулевую высоту — компонент занимает `100%` от него.
Классическая ошибка джуна: положить карту в `div` без высоты и полчаса искать,
почему экран пустой. 📏

Фиксированное разрешение и свой цвет:

```tsx
<H3Grid
  resolution={9}          // 📏 ровно 9-е разрешение H3, независимо от зума
  color="#22d3eeaa"       // 🎨 альфа — последние два символа hex
  center={[37.6173, 55.7558]}
  zoom={12}
  onClick={(h3) => console.log('выбрана ячейка', h3)}
/>
```

## 3. Все пропсы

| Проп | Тип | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `resolution` | `number \| 'auto'` | `'auto'` | Разрешение H3 (0…15) или автоподбор по зуму |
| `targetEdgePixels` | `number` | `40` | Желаемый размер ребра в пикселях (только для `'auto'`) |
| `maxCells` | `number` | `60000` | Предохранитель: выше — сетка не строится |
| `color` | `string \| [r,g,b,a]` | белый 35 % | Цвет линий; строка — CSS hex/rgba, массив — каналы 0..1 |
| `highlightColor` | `string \| [r,g,b,a]` | янтарный | Цвет контура ячейки под курсором |
| `highlight` | `boolean` | `true` | Подсвечивать ли ячейку под курсором |
| `debounceMs` | `number` | `120` | Задержка пересчёта после движения карты |
| `center` / `zoom` | | Москва, 11 | Начальный вид |
| `minZoom` / `maxZoom` | `number` | — | Ограничения зума |
| `mapStyle` | `string \| StyleSpecification` | OSM | Подложка |
| `onHover` | `(h3 \| null) => void` | — | Ячейка под курсором |
| `onClick` | `(h3) => void` | — | Ячейка, по которой кликнули |
| `onGrid` | `(info: GridInfo) => void` | — | Статистика после пересборки |
| `tooltip` | `false \| (h3) => ReactNode` | индекс ячейки | Подсказка |
| `children` | `ReactNode` | — | Своя панель поверх карты |

`GridInfo` — это `{ resolution, cells, ms, overflow }`: разрешение, число ячеек,
время построения в миллисекундах и флаг «сработал предохранитель».

## 4. Как это работает внутри

Порядок ровно такой, в каком выполняется код.

```
движение карты
   ↓ дебаунс 120 мс
1. взять bbox экрана          ← map.getBounds()
2. расширить его на 8 %       ← padBBox
3. выбрать разрешение         ← resolutionForEdgePixels (режим 'auto')
4. ОЦЕНИТЬ число ячеек        ← estimateCellCount   🛡️ предохранитель
5. получить список ячеек      ← cellsForBBox → polygonToCells
6. построить буфер линий      ← buildGridMesh
7. залить в видеопамять       ← H3GridLayer.setMesh
8. нарисовать одним вызовом   ← gl.drawArrays(gl.LINES, …)
```

### 4.1. Почему bbox расширяется (шаг 2)

`polygonToCells` возвращает ячейки, **центр** которых внутри полигона. Ячейка,
центр которой на полпикселя за краем экрана, в список не попадёт — и по краю
карты сетка оборвётся зубцами. Запас в 8 % решает это без заметной платы.

### 4.2. Автоподбор разрешения (шаг 3)

`resolutionForEdgePixels` идёт от разрешения 0 к 15 и берёт первое, у которого
ребро на экране стало меньше `targetEdgePixels`. Функция `edgePixels` (из
`geometry.ts`) считает это так:

```
метры на пиксель = 40075016.686 · cos(широта) / (512 · 2^зум)
ребро в пикселях = средняя длина ребра H3 (м) / метры на пиксель
```

Число 512 — размер тайла MapLibre на нулевом зуме, `cos(широта)` — поправка на
то, что в меркаторе масштаб растёт к полюсам.

В итоге при `'auto'` сетка выглядит одинаково плотной на любом зуме: приблизили —
разрешение стало мельче на шаг.

### 4.3. Предохранитель (шаг 4) — самое важное место 🛡️

Шаг разрешения H3 — это **в 7 раз больше ячеек** на той же площади. Разрешение 12
в масштабе города — это десятки миллионов ячеек, и `polygonToCells` на таком
запросе не «подтормозит», а намертво повесит вкладку на минуты.

Поэтому сначала считается дешёвая оценка «площадь экрана / средняя площадь ячейки»
(`estimateCellCount`, чистая арифметика, доли микросекунды), и только если она
меньше `maxCells` — вызывается настоящее построение.

Когда предохранитель сработал, сетка становится пустой, а в `onGrid` приходит
`overflow: true`. В демо на это показывается предупреждение «приблизьте карту».
**Не убирайте эту проверку**, даже если кажется, что «у нас так не бывает».

### 4.4. Дедупликация рёбер (шаг 6) — вторая по важности идея ➖

У двух соседних гексагонов ребро общее. Если рисовать по 6 рёбер на ячейку,
каждая внутренняя линия ляжет **дважды**: она станет вдвое ярче соседних
(при полупрозрачном цвете это отлично видно) и вершин будет вдвое больше.

Сравнивать вершины геометрически нельзя: на гранях икосаэдра H3 вставляет в
контур дополнительные точки, и у двух соседей общее ребро описано **разным**
числом вершин. Поэтому дедупликация топологическая:

- `originToDirectedEdges(h3)` даёт 6 направленных рёбер (у пентагона — 5);
- `getDirectedEdgeDestination(edge)` говорит, кто с той стороны;
- если сосед тоже есть в сетке, ребро оставляем за тем из двух, чей индекс
  лексикографически меньше (`if (present.has(neighbor) && h3 > neighbor) continue`);
- если соседа в сетке нет — это внешний край, рисуем всегда.

Проверить, что это работает, легко: на каждую ячейку должно приходиться
**≈3 сегмента, а не 6**. В консоли демо это ровно так: 3.05…3.34
(чуть больше трёх — за счёт края сетки и вставленных вершин).

### 4.5. Точность координат (origin)

Вершины хранятся не в мировых меркаторовских координатах, а **относительно первой
точки** (`origin`). Причина: `Float32Array` даёт около 7 значащих цифр, а на зуме
17 нужно больше — иначе линии начинают «дрожать» при панораме.

Обратный сдвиг вносится не в вершины, а в **матрицу проекции** (функция
`translated` в `H3GridLayer.ts`), пока числа ещё `double`. Это стандартный приём
для GPU-слоёв карт, и он же используется в `H3HexLayer`.

### 4.6. Отрисовка (шаг 8)

`H3GridLayer` — это `CustomLayerInterface` MapLibre: карта отдаёт нам свой
WebGL-контекст и матрицу проекции на каждый кадр, а мы рисуем что хотим.

Вся сетка экрана — **один** `gl.drawArrays(gl.LINES, …)`. Шейдеры минимальные:
вершинный только умножает точку на матрицу, фрагментный возвращает единственный
uniform-цвет. Смена цвета поэтому не требует перестроения геометрии — просто
новое значение uniform на следующем кадре.

### 4.7. Пикинг: какая ячейка под курсором ⚡

Никакого рендера в offscreen-буфер и никакого перебора полигонов. Индекс
считается прямо из координат курсора:

```ts
latLngToCell(lat, lng, resolution)
```

Это O(1) и не стоит ни одного лишнего кадра. Именно поэтому подсказка работает
одинаково быстро и на 100 ячейках, и на 60 000.

## 5. Как менять под себя

**Сделать сетку крупнее/мельче.** В режиме `'auto'` — крутите `targetEdgePixels`
(больше значение → крупнее гексагоны). Нужна привязка к конкретному разрешению
данных — передайте `resolution={9}` числом.

**Свой закон «зум → разрешение».** Автоподбор намеренно спрятан внутрь. Если
нужна своя логика, держите разрешение в состоянии родителя и меняйте его на
`onGrid`/событиях карты, передавая числом.

**Поднять лимит.** `maxCells={150000}` работает, но сначала померьте: в демо
6 700 ячеек строятся за ~90 мс в главном потоке. На 150 000 это уже заметная
пауза — если она нужна, стройте меш в Web Worker так же, как это сделано для
`H3Map` (см. `meshClient.ts` и `meshWorker.ts`): модуль `gridGeometry.ts`
специально не знает ни про React, ни про WebGL и переносится в воркер как есть.

**Толщина линий.** В WebGL `lineWidth` больше 1 не поддерживается почти нигде —
это ограничение спецификации, а не библиотеки. Нужны толстые линии — рисуйте их
треугольниками (каждый отрезок как прямоугольник из двух треугольников); это
заметно больше кода, поэтому здесь не сделано.

**Своя подложка вместо OSM.** `mapStyle={...}` — любой стиль MapLibre. Тайлы
`tile.openstreetmap.org` подходят для разработки; для продакшена возьмите
своего провайдера.

**Использовать слой без компонента.** Слой самодостаточен:

```ts
import { H3GridLayer, cellsForBBox, buildGridMesh } from 'react-h3-map';

const layer = new H3GridLayer();
map.addLayer(layer);
layer.setMesh(buildGridMesh(cellsForBBox([37.4, 55.6, 37.8, 55.9], 9), 9));
```

## 6. Частые грабли 🪤

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Пустой экран | у родителя нулевая высота | задать высоту контейнеру |
| Сетка не появляется, `cells: 0` | сработал предохранитель | смотреть `overflow` в `onGrid`, приблизить карту или поднять `maxCells` |
| Вкладка виснет | `maxCells` подняли слишком высоко на мелком разрешении | вернуть лимит, считать в воркере |
| Линии на стыках ярче | сломана дедупликация рёбер | сегментов на ячейку должно быть ≈3, а не ≈6 |
| Сетка «дрожит» на зуме 17+ | потерян `origin` | сдвиг должен уходить в матрицу, а не в вершины |
| Подсветка съехала от гексагона | контур построен на старом `origin` | `setMesh` пересчитывает подсветку — не обходите его |
| Линии не видно на светлой подложке | белый цвет с альфой 0.35 | задать тёмный `color` |

## 7. Демо

**▶️ [Открыть в браузере](https://akprof2000.github.io/Demo-H3-Hex/)** — собирается
из этой же ветки GitHub Actions при каждом пуше в `main`.

Локально:

```bash
npm run dev
```

Откроется `http://localhost:5180`. В правом верхнем углу — переключатель:

- **Сетка гексагонов** (`example/GridDemo.tsx`) — этот компонент: выбор
  разрешения, ползунок размера ребра, цвет линий, счётчики ячеек и времени;
- **Тепловая карта** (`example/HeatDemo.tsx`) — прежнее демо `H3Map` с данными RSRP.

Переключатель пересоздаёт компонент через `key`, чтобы старая карта корректно
освободила свой WebGL-контекст: их у браузера всего около 16 на вкладку. 🧹
