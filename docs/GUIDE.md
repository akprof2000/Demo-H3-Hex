## 1. Что вообще делает библиотека

На вход приходит массив вида:

```json
[["891fb46622fffff", 42.5], ["891fb46627bffff", 17.0]]
```

Первый элемент пары — **индекс H3**, второй — **число** (метрика: плотность,
выручка, количество заказов — что угодно).

На выход — карта OpenStreetMap, поверх которой залиты шестиугольники, окрашенные
по этому числу. При наведении показывается подсказка, снизу справа — легенда.

### Что такое H3

H3 — это система, которая разбивает поверхность Земли на шестиугольники.
Каждому шестиугольнику соответствует строковый индекс, например `891fb46622fffff`.

Ключевое понятие — **разрешение** (resolution), число от 0 до 15:

| Разрешение | Примерный размер ребра | На что похоже |
| --- | --- | --- |
| 6 | ~3.2 км | район города |
| 9 | ~174 м | квартал |
| 12 | ~9 м | двор |
| 14 | ~1.2 м | крыльцо |

Чем больше число, тем мельче ячейки и тем их больше. Библиотека умеет
подбирать разрешение под текущий зум карты — см. раздел 5.

## 2. Из чего состоит проект

```
src/
  types.ts        📚 общие типы — начинать чтение стоит отсюда
  palette.ts      🎨 число → цвет (таблица поиска)
  geometry.ts     📐 индексы H3 → вершины, треугольники, рёбра
  H3HexLayer.ts   🖼️ WebGL-слой MapLibre, вся отрисовка
  meshWorker.ts   🧵 та же геометрия, но в фоновом потоке
  meshClient.ts   🤝 мост «главный поток ↔ воркер»
  viewport.ts     🔭 подгрузка данных по видимой области
  H3Map.tsx       🧩 React-компонент, который всё это связывает
  Legend.tsx      🌈 легенда палитры
  mapStyle.ts     🗺️ стиль карты по умолчанию (растровый OSM)
  H3Grid.tsx      🕸️ сетка гексагонов на весь экран (см. GRID.md)
  H3GridLayer.ts  ➖ её WebGL-слой: только линии
  gridGeometry.ts 🧮 ячейки по экрану и геометрия сетки
example/          🧪 демо-приложение (Москва)
```

Зависимости — только `react`, `maplibre-gl` и `h3-js`. Ни deck.gl, ни d3, ни
turf здесь нет: всё, что нужно, — это триангуляция выпуклого шестиугольника,
а она делается в восемь строк.

## 3. Путь данных: от ответа сервера до пикселя

```
fetchData(viewport)          🔭 запрос по видимой области
        ↓  [[h3, value], ...]
ColorScale                   🎨 значение → цвет через таблицу на 512 ступеней
        ↓
buildMesh()                  📐 cellToBoundary → Web-Mercator → треугольники
        ↓  Float32Array + Uint8Array + Uint32Array
H3HexLayer.upload()          ⬆️ буферы уезжают в видеопамять
        ↓
render()                     🎬 ОДИН drawElements на все гексагоны
```

Разберём каждый шаг.

### 3.1 Палитра (`palette.ts`)

Наивный подход — на каждый гексагон интерполировать цвет между опорными
точками палитры. На 100 000 ячеек это 100 000 интерполяций.

Здесь сделано иначе: при создании `ColorScale` палитра **один раз**
разворачивается в таблицу (LUT) на 512 записей по 4 байта. Дальше цвет ячейки —
это одно умножение и чтение из массива:

```ts
offset(value) {
  let i = (value - this.min) * this.scale;   // значение → номер ступени
  i = clamp(i, 0, 511);                      // выбросы прижимаем к краям
  return (i | 0) * 4;                        // `| 0` — быстрое отбрасывание дроби
}
```

**Как поменять под себя:** передайте свои `colors` в проп `palette`. Опорных
цветов может быть сколько угодно, они распределяются равномерно по диапазону.

#### Дискретная шкала (пороги вместо градиента)

Для инженерных показателей градиент обычно не нужен: важны именно пороги.
Классический пример — RSRP (мощность опорного сигнала LTE/NR, дБм). Задайте
`bins` вместо `colors`:

```tsx
import { RSRP_PALETTE } from 'react-h3-map';

<H3Map palette={RSRP_PALETTE} domain={[-200, 0]} />
```

`RSRP_PALETTE` устроена так:

```ts
bins: [
  { from: -70,  to: 0,    color: '#1414ff', label: '-70 … 0' },     // синий
  { from: -90,  to: -70,  color: '#1c7a1c', label: '-90 … -70' },   // тёмно-зелёный
  { from: -100, to: -90,  color: '#78d278', label: '-100 … -90' },  // светло-зелёный
  { from: -110, to: -100, color: '#f0a83c', label: '-110 … -100' }, // оранжевый
  { from: -118, to: -110, color: '#f03232', label: '-118 … -110' }, // красный
  { from: -200, to: -118, color: '#101010', label: '-200 … -118' }, // чёрный
]
```

Границы диапазонов: нижняя включительно, верхняя исключительно, то есть
ровно −90 дБм попадает в «−90 … −70». Значения, не попавшие ни в один
диапазон, красятся в `noDataColor` и в легенде идут строкой «без значения».

Легенда в этом режиме сама превращается в список диапазонов и, если передан
массив ячеек, считает **долю ячеек в каждом** — как в отраслевых ГИС.

Под свой показатель просто скопируйте структуру и поставьте свои границы:

```ts
const SINR_PALETTE = {
  colors: [],
  opacity: 0.85,
  bins: [
    { from: 20, to: 40, color: '#1414ff', label: '20 … 40 дБ' },
    { from: 10, to: 20, color: '#1c7a1c', label: '10 … 20 дБ' },
    { from: -10, to: 10, color: '#f0a83c', label: '-10 … 10 дБ' },
  ],
};
```

### 3.2 Геометрия (`geometry.ts`)

Для каждой ячейки:

1. `cellToBoundary(h3)` — получаем контур: 6 точек `[lng, lat]`
   (иногда 7 или 10 — h3 вставляет дополнительные вершины на стыках граней
   икосаэдра, из которого построена сетка);
2. переводим в **Web-Mercator** — систему координат, в которой работает MapLibre:
   квадрат `[0..1] × [0..1]` на весь мир;
3. вычитаем **origin** — координату самой первой вершины (зачем — в разделе 4);
4. режем многоугольник на треугольники «веером»: `0-1-2`, `0-2-3`, `0-3-4`…
   Для выпуклой фигуры (а шестиугольник выпуклый) этого достаточно, никакой
   earcut не нужен.

Всё складывается в три плоских массива:

| Массив | Тип | На что |
| --- | --- | --- |
| `positions` | `Float32Array` | 2 числа на вершину |
| `colors` | `Uint8Array` | 4 байта (RGBA) на вершину |
| `indices` | `Uint32Array` | 3 числа на треугольник |

Массивы аллоцируются с запасом (10 вершин на ячейку) и в конце подрезаются
через `subarray` — так мы обходимся без `push` в обычный массив, который
переаллоцировался бы десятки раз.

### 3.3 Отрисовка (`H3HexLayer.ts`)

MapLibre разрешает встроить в свой конвейер собственный слой — нужно реализовать
интерфейс с методами `onAdd`, `render`, `onRemove`. Мы получаем готовый
WebGL-контекст и матрицу проекции, а рисуем сами.

Итог — **один `drawElements` на кадр**, независимо от того, 100 у вас
гексагонов или 100 000. Именно поэтому карта не тормозит при панораме.

## 4. Три неочевидных решения

Если вы будете править код, эти три места легко сломать по незнанию.

### 4.1 Origin-сдвиг: почему координаты хранятся «относительно»

`Float32` держит примерно 7 значащих цифр. Координата в Web-Mercator — это
число вроде `0.6046861111`. На зуме 16 разница между соседними пикселями
оказывается в районе восьмой-девятой цифры — то есть **за пределами точности
float32**. Результат: гексагоны дрожат и разъезжаются при панораме.

Решение: вычитаем из всех вершин координату первой (`origin`) — числа становятся
маленькими, и точности хватает с избытком. А обратный сдвиг вносим в матрицу
проекции, пока она ещё в двойной точности:

```ts
// H3HexLayer.ts
const matrix = translated(raw, mesh.origin[0], mesh.origin[1]);
```

### 4.2 Пикинг без второго прохода рендера

Обычный способ узнать, что под курсором, в GPU-графике — нарисовать сцену
второй раз в невидимый буфер, где цвет каждого объекта кодирует его id, и
прочитать пиксель. Это стоит целого дополнительного кадра.

Здесь этого не нужно: H3 — **вычислимая** сетка. Зная координаты курсора и
разрешение, индекс ячейки считается напрямую:

```ts
const h3 = latLngToCell(lat, lng, resolution);
const value = lookup.get(h3);   // O(1)
```

### 4.3 Границы между цветами: почему через directed edges

Режим обводки `boundary` рисует линию только там, где встречаются два разных
цвета. Напрашивается решение «сравнить координаты вершин соседних ячеек и
выкинуть совпавшие рёбра» — и оно **не работает**.

Причина: на гранях икосаэдра h3 вставляет дополнительные вершины, поэтому одно
и то же общее ребро у двух соседей описано разным числом точек. Геометрическое
сравнение их не сопоставит.

Правильный путь — топологический. У каждой ячейки есть 6 (у пентагона 5)
направленных рёбер, и каждое знает своего соседа:

```ts
for (const edge of originToDirectedEdges(h3)) {
  const neighbor = getDirectedEdgeDestination(edge);
  // сосед того же цвета → линия не нужна
  // сосед другого цвета → рисуем, но только с одной стороны (h3 < neighbor)
  // соседа нет в данных → это внешний контур, рисуем всегда
}
```

## 5. Адаптивная обводка

Обводка гексагонов выглядит хорошо только когда они крупные. На мелких она
превращает карту в серую рябь. Поэтому режим выбирается автоматически по
**размеру ребра на экране**:

| Ребро на экране | Режим | Что рисуется |
| --- | --- | --- |
| ≥ 14 px | `all` | вся сетка |
| 4…14 px | `boundary` | только границы между разными цветами |
| < 4 px | `none` | ничего |

Размер считается из разрешения H3, зума и широты:

```ts
const metersPerPixel = 40075016.686 * cos(lat) / (512 * 2 ** zoom);
const px = getHexagonEdgeLengthAvg(resolution, 'm') / metersPerPixel;
```

**Как поменять под себя:**

```tsx
// сдвинуть пороги
<H3Map stroke={{ thresholds: { all: 20, boundary: 6 } }} />

// зафиксировать режим
<H3Map stroke={{ mode: 'all' }} />

// свой цвет линий (RGBA, каналы 0..1)
<H3Map stroke={{ color: [1, 1, 1, 0.5] }} />

// выключить совсем
<H3Map stroke={false} />
```

## 6. Подгрузка по видимой области

`fetchData` вызывается при `moveend` и `zoomend`. Три защиты работают вместе:

1. **Дебаунс** (по умолчанию 200 мс) — при панораме событий десятки,
   запрос уходит один;
2. **AbortSignal** — предыдущий запрос отменяется, сигнал передаётся в `fetch`;
3. **Номер запроса** — если ответы вернулись не в том порядке, старый
   отбрасывается по номеру.

```tsx
<H3Map
  fetchData={async (vp, signal) => {
    const r = await fetch(
      `/api/hexes?bbox=${vp.bbox.join(',')}&res=${vp.resolution}`,
      { signal }   // ← обязательно пробросьте signal
    );
    return r.json();
  }}
/>
```

### Фиксированный диапазон значений

По умолчанию цвета растягиваются на min/max **текущих** данных — при смене
вьюпорта они «прыгают». Обычно это не то, что нужно. Два способа зафиксировать:

```tsx
// вариант A: знаем диапазон заранее
<H3Map domain={[0, 1000]} />
```

```ts
// вариант B: бэкенд возвращает его вместе с данными
return { cells: [...], domain: [0, 1000] };
```

Приоритет: проп `domain` → `domain` из ответа → min/max по данным.

## 7. Web Worker

Сборка геометрии — чистые вычисления, и на 100 000 ячейках она занимает
~250 мс. На главном потоке это заметный фриз.

`MeshBuilder` решает сам: до `workerThreshold` (по умолчанию 20 000 ячеек)
считает на месте — переброс в воркер дороже самой работы; выше — отдаёт в
фоновый поток. Буферы возвращаются через `transferable`, то есть **без
копирования**.

Воркер один, и побеждает последний запрос: при быстром зуме промежуточные
результаты всё равно никто не увидит.

Если ваш сборщик не резолвит путь к воркеру автоматически, передайте фабрику:

```tsx
<H3Map
  workerFactory={() =>
    new Worker(new URL('react-h3-map/dist/meshWorker.js', import.meta.url), {
      type: 'module',
    })
  }
/>
```

## 8. Частые доработки

### Свой источник тайлов

Тайлы `tile.openstreetmap.org` годятся для разработки, но их
[Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/)
запрещает серьёзный продовый трафик.

```tsx
import { osmStyle } from 'react-h3-map';

<H3Map mapStyle={osmStyle(['https://tiles.example.com/{z}/{x}/{y}.png'])} />
// или полноценный векторный стиль:
<H3Map mapStyle="https://example.com/style.json" />
```

### Свой тултип

```tsx
<H3Map
  tooltip={(info) => (
    <div>
      <b>{info.value.toFixed(1)}</b> заказов
      <div>{info.h3}</div>
    </div>
  )}
/>
```

### Своя панель поверх карты

Всё, что передано в `children`, рендерится поверх карты:

```tsx
<H3Map fetchData={fetcher}>
  <div style={{ position: 'absolute', top: 10, left: 10 }}>Моя панель</div>
</H3Map>
```

### Слой без React

`H3HexLayer` не зависит от React — его можно добавить в любую карту MapLibre:

```ts
const layer = new H3HexLayer();
map.addLayer(layer);
layer.setData(cells, new ColorScale(DEFAULT_PALETTE, [0, 100]), { edges: 'all' });
```

### Своё соответствие зума и разрешения

```tsx
// демо по Москве: от 6 (город целиком) до 14 (отдельный дом)
<H3Map resolutionForZoom={(z) => Math.min(14, Math.max(6, Math.round(z) - 3))} />
```

## 10. Известные ограничения

- **Толщина линий.** WebGL рисует линии толщиной 1 пиксель; параметр `lineWidth`
  большинство браузеров игнорирует. Для по-настоящему толстой обводки линии
  пришлось бы разворачивать в треугольники — для v1 это сочли лишним.
- **Смена стиля карты.** Карта создаётся один раз; чтобы поменять `mapStyle`
  на лету, нужно вызвать `map.setStyle()` и заново добавить слой.
- **Смешанные разрешения.** Пикинг перебирает все разрешения, встреченные в
  данных, от мелких к крупным. Работает, но на смеси из 5+ разрешений это
  5+ вычислений индекса на движение мыши.
- **Полюса.** Широта подрезается на ±85.051129° — за этой границей меркатор
  уходит в бесконечность.
